AI-Driven Development Life Cycle · AWS / Raja SP · Jul 2025

Three Phases

Each phase enriches context for the next
I Inception Mob Elaboration

Captures an Intent and decomposes it into Units and Bolts. Mob Elaboration runs in a single room with a shared screen — entire team (PO, devs, QA, stakeholders) reviewing and refining AI outputs in real time. Condenses weeks of sequential planning into hours.

Agent AI asks clarifying questions — surfaces ambiguity in the original intent before elaborating (e.g. "Who are the primary users? What key business outcomes should this achieve?")
Agent AI elaborates intent — generates user stories, NFRs, risk descriptions, and composes stories into Units using loose coupling / high cohesion principles.
Human Mob reviews + corrects — adjusts over/under-engineered parts, adds real-world constraints (e.g. GDPR), validates units align with business objectives.
Agent AI generates PRFAQ (optional) — summarizes business intent, functionality, expected benefits. Also proposes suggested Bolts for executing each Unit.
Human PO validates outputs — approves PRFAQ, risk descriptions, measurement criteria, and the Bolt breakdown before Construction begins.

Outputs: PRFAQ · User Stories · NFR definitions · Risk descriptions · Measurement criteria · Suggested Bolts

II Construction Mob Construction

Transforms Units into tested, operations-ready Deployment Units. Progresses through four sub-stages: Domain Design → Logical Design → Code → Test. Developers validate AI outputs at each stage — human oversight functions as a loss function, catching errors before they compound downstream.

Agent Domain Design — AI models business logic using DDD: aggregates, value objects, entities, domain events, repositories, factories. Independent of infrastructure.
Human Devs validate domain model — refine business logic, handle real-world edge cases (e.g. how to handle new customers with no purchase history).
Agent Logical Design — AI applies NFRs (scalability, fault tolerance) to domain model, recommends patterns (CQRS, Circuit Breakers, event-driven) and AWS services. Generates ADRs for review.
Human Devs approve trade-offs — accept or override AI's architectural decisions (e.g. accept Lambda for scalability but override storage to DynamoDB).
Agent Code + tests generated — AI implements from Logical Design, maps to AWS services, auto-generates functional, security, and performance tests.
Human Devs review code + test scenarios — adjust for quality and compliance before AI executes the test suite.
Agent AI executes tests + proposes fixes — runs all suites, analyzes results, correlates failures with code or config changes, proposes specific fixes.
Human Devs validate + approve fixes — confirm AI findings, authorize reruns. Brown-field adds a prior step: AI reverse-engineers static + dynamic models of existing code first.

Outputs: Domain Design · Logical Design · ADRs · Code · Test suites · Deployment Unit

III Operations Team Oversight

AI analyzes telemetry (metrics, logs, traces) to detect anomalies and predict SLA violations proactively. Integrates with incident runbooks to propose actionable resolutions. Developers serve as validators — AI acts, humans approve.

Agent AI packages Deployment Units — container images, serverless functions (Lambda), IaC (Terraform/CFN/CDK). Generates validation plan and report.
Human Devs approve + initiate rollout — review deployment config, approve to staging then production.
Agent AI monitors telemetry — detects latency spikes, error rate anomalies, and predicts SLA violations (e.g. recommends DynamoDB throughput increase during traffic spike).
Agent AI integrates with runbooks — proposes resource scaling, performance tuning, or fault isolation. Executes resolutions only after developer approval.
Human Devs validate + approve — confirm AI recommendations align with SLAs and compliance requirements, monitor resolution outcomes.

Core Loop

AI initiates — humans validate. Repeats at every level.
1
AI Generates Plan Agent
AI initiates by producing a Level 1 plan for the current intent. Decomposed recursively to Level 2, Level 3 — each level under human oversight before the next is generated.
2
AI Seeks Clarification Agent
AI asks targeted questions before implementing — surfacing ambiguity in intent, constraints, or trade-offs. Only humans have the contextual business knowledge to answer.
3
Human Validates Human
Team reviews, corrects, and approves AI's plan. Acts as a loss function — catching errors before they compound. Critical decisions never delegated to AI.
4
AI Implements Agent
With validated context, AI executes — stories, domain models, code, tests, IaC. All artifacts persisted as "context memory" referenced throughout the lifecycle.

Artifacts

Work hierarchy from intent to deployment
I Intent

High-level statement of purpose — a business goal, feature, or technical outcome. Starting point for all AI-driven decomposition.

U Unit ≈ Epic / Subdomain

Cohesive, self-contained block of work derived from an Intent. Loosely coupled — enables parallel Bolt execution by independent teams.

B Bolt ≈ Sprint (hours–days)

Smallest iteration — implements one Unit or subset of its stories. Multiple Bolts per Unit, running in parallel or sequentially.

DD Domain Design

DDD model of business logic — aggregates, value objects, entities, domain events, repositories. Infrastructure-independent.

LD Logical Design

Domain Design + NFRs + cloud patterns (CQRS, Circuit Breakers). Produces ADRs for developer validation before code is written.

DU Deployment Unit

Packaged executable — container image, Lambda function, or IaC stack. Tested for functional, security, and NFR compliance before deploy.
