AI Primer

Personal study reference — terminology grouped by topic
Foundation
The Field
Machine Learning (ML)
The broader field of algorithms that learn patterns from data instead of being explicitly programmed. AI is the goal; ML is the method.
Deep Learning
A subset of ML using neural networks with many layers. The "deep" refers to layer depth. Powers all modern LLMs, image recognition, and speech models.
Neural Network
Layers of interconnected nodes (neurons) that transform input into output. Each connection has a weight. Deep networks have many layers.
Types of AI
Narrow AI
AI that excels at one specific task — chess, image recognition, language — but cannot generalise. All current AI systems are narrow AI.
AGI (Artificial General Intelligence)
Hypothetical AI that matches or exceeds human-level reasoning across all domains. Does not yet exist. Active research area at Anthropic, OpenAI, DeepMind.
Predictive AI
Classifies or forecasts based on patterns in training data. Outputs a category or number. e.g. spam filter, fraud detection, demand forecast.
Generative AI
Produces new content — text, images, code, audio — rather than classifying input. LLMs are generative.
Discriminative Model
Learns the boundary between classes. Asks "given this input, which class?" Contrast with generative models that learn the data distribution itself.
Multimodal
A model that accepts multiple input types: text, images, audio, video. Claude 3+ is multimodal — it can read images as well as text.
Models
Large Language Model (LLM)
A neural network trained on massive text corpora to predict the next token. Claude, GPT-4, Gemini are LLMs.
Foundation Model
A large model trained on broad data that can be adapted to many tasks. LLMs are a type of foundation model.
Core Process
Parameters / Weights
The numerical values inside a model learned during training. More parameters = more capacity. GPT-4 has ~1 trillion.
Training
Adjusting a model's weights by showing it examples and minimising prediction error. Happens once (or rarely) — not at inference time.
Inference
Running a trained model to get a prediction or response. What happens every time you send a message to Claude.
Model
The trained artifact — a set of weights that maps inputs to outputs. "Calling the model" means running inference against these weights.
How LLMs Work
Input & Output
Prompt
The full input sent to the model — system message + user message combined. Everything the model sees before generating a response.
Completion
The model's generated response. Also called the "output" or "response." The model produces completions one token at a time.
Token
The unit of text an LLM processes. Roughly 0.75 words. "Hello Scrum" = 3 tokens. Models have a maximum token limit per call.
Tokenisation
Splitting text into tokens before the model processes it. Different models use different tokenisers. Affects cost and context limits.
Context Window
The maximum tokens a model can process in a single call — both input and output combined. Claude's window is 200k tokens.
Streaming
Receiving tokens as they're generated rather than waiting for the full response. Hello Scrum uses SSE streaming so the log updates in real time.
System Prompt
Instructions given before the conversation starts. Sets role, behaviour, and constraints. Not shown to the end user.
User Prompt
The input from the human turn. In agent pipelines this often includes injected context — file contents, data, dynamic instructions.
Multi-turn
A conversation with multiple back-and-forth exchanges. Each turn adds to the context window. Used in story elaboration's tool-use loop.
Architecture
Transformer
The neural network architecture behind all modern LLMs. Introduced in "Attention is All You Need" (2017). Uses self-attention to process sequences in parallel.
Attention
The mechanism that lets a model weigh which parts of the input are relevant to each token it generates. Core of the Transformer architecture.
Embedding
A vector (list of numbers) representing the meaning of text. Similar meanings = similar vectors. Foundation of semantic search and RAG.
Latent Space
The high-dimensional space where embeddings live. Similar concepts cluster together. The model "understands" language by navigating this space.
Pre-training
The initial large-scale training on broad data (books, web, code) before fine-tuning. Gives the model general language understanding.
Output Control
Temperature
Controls randomness. Low (0) = deterministic. High (1+) = creative, picks less likely tokens more often.
Top-p (Nucleus Sampling)
Limits token selection to the smallest set whose cumulative probability exceeds p. Cuts off unlikely tokens.
Top-k
Limits token selection to the k most likely candidates at each step. Often used together with top-p.
Structured Output
Asking the model to respond in a specific format — JSON, XML, a schema. All 14 Hello Scrum prompts use structured output. Reduces parsing errors.
Failure Modes
Hallucination
When a model generates plausible-sounding but factually incorrect content. Caused by predicting probable text rather than retrieving ground truth.
Instruction Following
The model's ability to follow explicit directions accurately. Poor instruction following = model ignores constraints or output format rules.
Prompt Engineering
Prompting Techniques
Zero-shot
Asking the model to do a task with no examples — just instructions. Works for simple tasks; fails on tasks requiring specific output formats.
One-shot
Providing one example of the desired input → output before asking the model to perform the task.
Few-shot
Providing 2–5 examples before asking the model. More examples = more reliable output format. Used in both Hermes prompts here.
Chain of Thought (CoT)
Asking the model to reason step by step before giving a final answer. Improves accuracy on complex tasks.
ReAct
Reason + Act pattern for agents. The model thinks, then acts, then observes the result, then repeats. Combines planning with tool use.
Structure
RTCC
Role → Task → Context → Constraints. A prompt structure that separates identity, task, knowledge, and rules.
XML Tags
Using <task>, <context>, <constraints> to structure prompt sections. Anthropic's recommended syntax — Claude parses them more reliably than prose headings.
Runtime Injection
Adding dynamic context to a prompt at call time — not hardcoded. e.g. injecting index.html content or wisdom bullets into the agent prompt.
Prompt Chaining
Using the output of one LLM call as the input to the next. Hello Scrum: RE → clarify → elaborate → agent.
Concepts
Grounding
Connecting model output to real, verifiable data. RAG is a grounding technique. Reduces hallucination by giving the model facts to reference.
Prompt Injection
An attack where malicious text overrides the system prompt's instructions. e.g. "Ignore previous instructions and..."
Prompt Versioning
Tracking prompt changes over time like code — with history, diffs, and rollback. Critical when prompt changes cause regressions in agent behaviour.
RAG & Knowledge
The Pattern
RAG (Retrieval Augmented Generation)
Relevant documents are retrieved from a knowledge base and injected into the prompt before generation. Grounds answers in real data without fine-tuning.
Knowledge Base
The collection of documents, facts, or data that a RAG system retrieves from. Internal docs, manuals, FAQs, and code are candidate knowledge bases.
Chunking
Splitting documents into smaller pieces before embedding. Too large misses specifics, too small loses context.
Context Stuffing
Loading everything into the context window rather than selectively retrieving. Simple but expensive. Works when the knowledge base is small enough to fit.
Vectors
Embedding
A vector representing the meaning of text in high-dimensional space. Generated by an embedding model. Similar meanings = similar vectors.
Vector
A list of numbers representing a piece of text. e.g. [0.2, 0.8, -0.3, ...] Used to measure semantic similarity.
Vector Database
A database optimised for storing and searching embeddings. e.g. Pinecone, Weaviate, pgvector. Finds semantically similar content fast.
Retrieval
Semantic Search
Finding content by meaning rather than exact keywords. "sprint velocity" returns results about throughput even if those words don't appear.
Hybrid Search
Combining keyword search (BM25) and semantic search (vector) for better retrieval. Keyword catches exact terms; semantic catches meaning. Often better than either alone.
Cosine Similarity
The most common way to measure how similar two vectors are. Returns -1 to 1. 1 = identical meaning, 0 = unrelated.
Re-ranking
A second pass that reorders retrieved chunks by relevance before injecting into the prompt. Improves RAG quality beyond raw vector similarity.
Retrieval Precision / Recall
Precision: how many retrieved chunks are actually relevant. Recall: how many relevant chunks were retrieved. Tradeoff — improving one often hurts the other.
Agents
Core
Agent
An LLM that can take actions — call tools, read files, write code, loop — not just respond to a single prompt.
Agentic Loop
A pattern where the agent runs repeatedly until a goal is met. Hello Scrum: pull → implement → test → review → deploy → repeat.
Scaffolding
The code and framework wrapping LLM calls — routing, retries, tool dispatch, logging. agent.py and server.py are the scaffolding in Hello Scrum.
Planning
An agent breaking a goal into steps before executing. ReAct is a common planning pattern: think, act, observe, repeat.
Capabilities
Tool / Action
A specific capability the agent can invoke: read_file, web_search, send_email. Tools have typed schemas — name, description, input parameters.
Tool Use / Function Calling
Giving an LLM the ability to call external functions with structured inputs. The model decides when and how. Used in story elaboration here.
Memory (Short-term)
The current context window — everything the model can "see" in this call. Lost when the call ends.
Memory (Long-term)
Persistent storage the agent reads/writes across calls. e.g. wisdom files, sdlc_pipeline.json. Must be explicitly loaded into context.
Feedback Loop
How outputs from one step feed into the next. Hello Scrum's wisdom loop is a feedback loop: retro findings → wisdom bullets → better next sprint.
Multi-Agent Patterns
Orchestration
Coordinating multiple agents or LLM calls to complete a complex task. The sprint pipeline (RE → clarify → elaborate → code → review → deploy) is orchestration.
Supervisor Agent
An orchestrator that routes tasks to specialist sub-agents. e.g. a router that sends coding tasks to a coder and review tasks to Hermes.
Handoff
Passing control and context from one agent to another. Each handoff includes the relevant state so the receiving agent has what it needs.
Multi-agent
Multiple specialised agents working in parallel or series. Hello Scrum is single-agent + one reviewer (Hermes). Full multi-agent routes work to many coders.
Human-in-the-Loop
A human reviews and approves agent decisions at key points. FD approval and Hermes review are human-in-the-loop gates in Hello Scrum.
WIP (Work in Progress)
How many items an agent works on simultaneously. AI-DLC enforces WIP=1 — one story at a time. Limits cascading failures.
Evaluation & Observability
Testing
Eval
A test that measures whether an AI system produces correct or acceptable outputs. The foundation of knowing if your agent is improving or degrading.
Ground Truth
The known correct answer used to evaluate model output. Building ground truth datasets is expensive but necessary for rigorous evals.
LLM-as-Judge
Using an LLM to evaluate another LLM's output. Hermes is an LLM-as-judge — evaluates the coding agent's patches and AC compliance.
Human Eval
Having humans rate or rank model outputs. Gold standard for quality but expensive and slow. Often used to calibrate automated evals.
A/B Testing
Comparing two prompt variants on the same inputs to see which performs better. Essential when changing prompts — change one thing at a time and measure.
Benchmark
A standardised evaluation dataset used to compare models. e.g. MMLU, HumanEval. Useful for model selection; less useful for task-specific evals.
Metrics
Pass Rate
The percentage of stories that pass all gates (tests + code review + AC check). Hello Scrum's leaderboard tracks this per sprint.
Latency
Time from prompt sent to response received. stage_times in Hello Scrum tracks per-stage latency.
Cost per Call
Input tokens × input price + output tokens × output price. Haiku is ~20× cheaper than Sonnet. Hello Scrum uses Haiku for review, Sonnet for coding.
Operations
Tracing
Recording every step of an agent's execution — prompts called, responses, timing. The audit log is tracing in Hello Scrum.
Regression
A previously passing test that now fails. In agent systems, regressions often appear after prompt changes — improving one task can break another.
Prompt Versioning
Tracking prompt changes over time like code — with history, diffs, and rollback. Critical when prompt changes cause regressions.
Fine-tuning & Training
Adapting Models
Fine-tuning
Further training a pre-trained model on a specific dataset to specialise its behaviour. Changes the model's weights. More durable than prompt engineering but more expensive.
Transfer Learning
Starting from a pre-trained model and adapting for a new task. Almost all LLM work is transfer learning — you start from a foundation model, not scratch.
LoRA (Low-Rank Adaptation)
Efficient fine-tuning that only updates a small set of added parameters rather than the whole model. Cheaper and faster than full fine-tuning.
Prompt Tuning
Trains a small set of "soft prompt" tokens prepended to every input, while keeping the base model frozen. Lighter than fine-tuning.
Training Concepts
RLHF (Reinforcement Learning from Human Feedback)
Humans rank model outputs and the model is trained to produce more preferred responses. How Claude and ChatGPT learned to be helpful and harmless.
Loss Function
The mathematical measure of how wrong the model's predictions are. Training minimises this. For LLMs: cross-entropy loss on next-token prediction.
Gradient Descent
The algorithm that adjusts model weights to reduce loss. Calculates which direction to nudge each weight to improve predictions.
Epoch
One complete pass through the training dataset. Multiple epochs = the model sees the same data multiple times. Risk: overfitting if too many.
Batch Size
How many training examples are processed together before weights are updated. Larger batches = more stable but slower training.
Learning Rate
How aggressively weights are adjusted each training step. Too high = unstable training. Too low = very slow convergence.
Overfitting
When a model memorises training examples instead of learning general patterns. Performs well on training data, poorly on new data.
Synthetic Data
AI-generated training data used when real labelled data is scarce. A model generates examples that are then used to train another (or itself).
Data
Datasets
Training Data
The examples a model learns from during training. Quality and diversity of training data directly determines model capability.
Dataset
A structured collection of examples — inputs, outputs, and often labels. Used for training, fine-tuning, or evaluation.
Labelling / Annotation
Adding ground truth labels to training examples. e.g. marking an email as spam/not-spam. Expensive but necessary for supervised learning.
Synthetic Data
AI-generated training data used when real labelled data is scarce. Growing in importance as models improve at generating realistic examples.
Quality
Data Curation
Selecting, cleaning, and organising data for training. Removing duplicates, filtering low-quality examples, balancing classes.
Data Quality
The accuracy, completeness, and consistency of training data. "Garbage in, garbage out" — poor data quality produces poor models regardless of architecture.
Class Imbalance
When training data has far more examples of some classes than others. A fraud detector trained on 99% non-fraud learns to always say "not fraud."
Data Drift
When real-world data distribution shifts away from training data over time. Model performance degrades. Requires monitoring and periodic retraining.
Infrastructure & APIs
API Basics
API (Application Programming Interface)
How you call the model programmatically. You send a request (prompt) and receive a response (completion). Anthropic's API is what Hello Scrum uses.
SDK (Software Development Kit)
A library that wraps API calls in your language. e.g. Anthropic Python SDK. Handles auth, retries, and response parsing.
Endpoint
The URL you send API requests to. e.g. api.anthropic.com/v1/messages. Different endpoints for different capabilities (messages, embeddings, etc.).
Model Version
A specific versioned release of a model. e.g. claude-sonnet-4-6. Pin your version in production — new versions can change behaviour.
Limits & Reliability
Rate Limit
Max requests or tokens per minute/day. Hitting a rate limit returns a 429 error. Plan capacity by estimating tokens per sprint × stories per sprint.
Tokens per Minute (TPM)
Throughput limit on how fast you can process tokens. More relevant than requests-per-minute for large context workloads.
Timeout
Max time to wait for a model response before failing. Long responses (large context + many output tokens) can take 60–120 seconds. Hello Scrum sets a 180s timeout.
Retry Logic
Automatically retrying failed API calls with exponential backoff. Handles transient errors (rate limits, network issues) without crashing the pipeline.
Prompt Caching
Caching repeated prompt prefixes (like a long system prompt) so they aren't re-processed each call. Reduces cost and latency for long static context.
Multimodal
Input Types
Multimodal Model
A model that accepts multiple input types: text, images, audio, video. Claude 3+ is multimodal — it can reason about images as well as text.
Vision
The ability to process and reason about images. Send an image + text prompt and the model describes, analyses, or answers questions about the image.
Image-to-text
Generating text descriptions or analysis from images. e.g. "What does this chart show?" or "Extract the table from this screenshot."
Cross-modal Reasoning
Reasoning that spans multiple modalities. e.g. "Compare this wireframe image to the description in the document." Requires a multimodal model.
Output Types
Text-to-image
Generating images from text descriptions. e.g. DALL-E, Midjourney, Stable Diffusion. Different models from LLMs — Claude generates text only.
Text-to-speech (TTS)
Generating spoken audio from text. Used in voice assistants and accessibility tools. Not the same model as an LLM.
Speech-to-text (STT)
Transcribing spoken audio to text. e.g. Whisper. Often used as a preprocessing step before sending to an LLM.
Safety & Ethics
Alignment
Alignment
Ensuring AI systems do what humans actually want — not just what they literally asked for. An aligned model is helpful, harmless, and honest.
Constitutional AI
Anthropic's technique for training Claude using a written set of principles (a "constitution") rather than purely human feedback.
AI Safety
The field focused on ensuring AI systems remain beneficial as they become more capable. Includes technical alignment research and governance/policy work.
Threats
Bias
Systematic errors reflecting imbalances in training data. A model trained mostly on one demographic will perform worse on others.
Jailbreak
A prompt designed to bypass a model's safety guardrails. Usually involves roleplay, hypotheticals, or instruction injection.
Prompt Injection
Malicious text in the input overrides the system prompt's instructions. A key security concern for any agent that processes external content.
Red Teaming
Deliberately trying to break or extract harmful outputs from an AI system. Standard practice before deploying models or agents.
Controls
Guardrails
Rules or filters that prevent a model from producing harmful outputs. Can be in the prompt (instructions) or external (output classifiers).
Content Filtering
Automated checks that block or flag harmful inputs or outputs. Can be a separate classifier model running alongside the main model.
Hallucination Mitigation
Techniques to reduce hallucination: grounding with RAG, lowering temperature, asking the model to cite sources, human review gates.
Explainability
The ability to understand why a model produced a specific output. LLMs are largely black boxes — chain of thought is one way to surface reasoning.
