Prompt Engineering
RTCC Format
All 14 prompts in Hello Scrum follow the Role → Task → Context → Constraints structure. Each section has a clear job: Role sets identity, Task states what to do, Context provides what the model needs to know, Constraints define what it must and must not do.
You are an AI-DLC Functional Design assistant. <task> Produce a concrete implementation plan for patching index.html. </task> <context> Injected at runtime: story, AC, workspace snapshot, index.html slice. </context> <constraints> - patch_target: always "index.html" - implementation_approach: 1 sentence, max 20 words </constraints>
XML Tags
Anthropic's recommended syntax for Claude prompts. Tags like <task>, <context>, and <constraints> make structure unambiguous. Claude is trained on XML-tagged inputs and parses them more reliably than prose headings.
Anthropic docs — XML tags
Few-Shot Examples
Showing the model a concrete approve/reject example before asking it to evaluate. Used in both Hermes prompts. A single well-chosen example dramatically reduces edge-case errors compared to rules alone.
See Hermes prompts →
Runtime Injection
Static prompts define structure. Dynamic context — workspace snapshot, functional design, wisdom bullets, the actual story — arrives in the user message at call time. This separation keeps prompts maintainable and context fresh.
See Live view on Prompts page →
Wisdom Loop
After every sprint, the retro synthesises findings into coding_wisdom.json and ac_wisdom.json. These are injected into the next sprint's coding agent and story elaboration prompts — the system learns from its own failures.
