AI Primer

Personal study reference — terminology grouped by topic
Foundation
Types of AI
Predictive AI
Classifies or forecasts based on patterns in training data. Outputs a category or number. e.g. spam filter, fraud detection, demand forecast.
Generative AI
Produces new content — text, images, code, audio — rather than classifying input. LLMs are generative.
Discriminative Model
Learns the boundary between classes. Asks "given this input, which class?" Contrast with generative models that learn the data distribution itself.
Models
Large Language Model (LLM)
A neural network trained on massive text corpora to predict the next token. Claude, GPT-4, Gemini are LLMs.
Foundation Model
A large model trained on broad data that can be adapted to many tasks. LLMs are a type of foundation model.
Neural Network
Layers of interconnected nodes (neurons) that transform input into output. Each connection has a weight. Deep networks have many layers.
Core Process
Parameters / Weights
The numerical values inside a model learned during training. More parameters = more capacity. GPT-4 has ~1 trillion.
Training
Adjusting a model's weights by showing it examples and minimising prediction error. Happens once — not at inference time.
Inference
Running a trained model to get a prediction or response. What happens every time you send a message to Claude.
Model
The trained artifact — a set of weights that maps inputs to outputs. "Calling the model" means running inference against these weights.
How LLMs Work
Input & Output
Token
The unit of text an LLM processes. Roughly 0.75 words. "Hello Scrum" = 3 tokens. Models have a maximum token limit per call.
Tokenisation
Splitting text into tokens before the model processes it. Different models use different tokenisers. Affects cost and context limits.
Context Window
The maximum tokens a model can process in a single call — both input and output combined. Claude's window is 200k tokens.
System Prompt
Instructions given to the model before the conversation starts. Sets role, behaviour, and constraints. Not shown to the end user.
User Prompt
The input from the human turn. In agent pipelines this often includes injected context — file contents, data, dynamic instructions.
Architecture
Embedding
A vector (list of numbers) representing the meaning of text. Similar meanings = similar vectors. Foundation of semantic search and RAG.
Attention
The mechanism that lets a model weigh which parts of the input are relevant to each token it generates. Core of the Transformer.
Transformer
The neural network architecture behind all modern LLMs. Introduced in "Attention is All You Need" (2017). Uses self-attention to process sequences in parallel.
Output Control
Temperature
Controls randomness. Low (0) = deterministic. High (1+) = creative, picks less likely tokens more often.
Top-p (Nucleus Sampling)
Limits token selection to the smallest set whose cumulative probability exceeds p. Cuts off unlikely tokens.
Top-k
Limits token selection to the k most likely candidates at each step. Often used together with top-p.
Failure Mode
Hallucination
When a model generates plausible-sounding but factually incorrect content. Caused by predicting probable text rather than retrieving ground truth.
Prompt Engineering
Prompting Techniques
Zero-shot
Asking the model to do a task with no examples — just instructions. Works for simple tasks; fails on tasks requiring specific output formats.
One-shot
Providing one example of the desired input → output before asking the model to perform the task.
Few-shot
Providing 2–5 examples before asking the model to perform the task. More examples = more reliable output format. Used in both Hermes prompts here.
Chain of Thought (CoT)
Asking the model to reason step by step before giving a final answer. Improves accuracy on complex tasks.
Structure
RTCC
Role → Task → Context → Constraints. A prompt structure that separates identity, task, knowledge, and rules.
XML Tags
Using <task>, <context>, <constraints> to structure prompt sections. Anthropic's recommended syntax — Claude parses them more reliably than prose headings.
Runtime Injection
Adding dynamic context to a prompt at call time — not hardcoded. e.g. injecting index.html content or wisdom bullets into the agent prompt.
Prompt Chaining
Using the output of one LLM call as the input to the next. Hello Scrum: RE → clarify → elaborate → agent.
Concepts
Grounding
Connecting the model's output to real, verifiable data. RAG is a grounding technique. Reduces hallucination by giving the model facts to reference.
Prompt Injection
An attack where malicious text in the input overrides the system prompt's instructions. e.g. "Ignore previous instructions and..."
RAG & Knowledge
The Pattern
RAG (Retrieval Augmented Generation)
Relevant documents are retrieved from a knowledge base and injected into the prompt before generation. Grounds answers in real data without fine-tuning.
Knowledge Base
The collection of documents, facts, or data that a RAG system retrieves from. Internal docs, manuals, FAQs, code are all candidate knowledge bases.
Chunking
Splitting documents into smaller pieces before embedding them. Chunk size affects retrieval quality — too large misses specifics, too small loses context.
Vectors
Embedding
A vector representing the meaning of text in high-dimensional space. Generated by an embedding model. Similar meanings = similar vectors.
Vector
A list of numbers representing a piece of text. e.g. [0.2, 0.8, -0.3, ...] Used to measure semantic similarity.
Vector Database
A database optimised for storing and searching embeddings. e.g. Pinecone, Weaviate, pgvector. Finds semantically similar content fast.
Retrieval
Semantic Search
Finding content by meaning rather than exact keywords. "sprint velocity" returns results about throughput even if those words don't appear.
Cosine Similarity
The most common way to measure how similar two vectors are. Returns -1 to 1. 1 = identical meaning, 0 = unrelated.
Re-ranking
A second pass that reorders retrieved chunks by relevance before injecting into the prompt. Improves RAG quality beyond raw vector similarity.
Agents
Core
Agent
An LLM that can take actions — call tools, read files, write code, loop — not just respond to a single prompt.
Agentic Loop
A pattern where the agent runs repeatedly until a goal is met. Hello Scrum: pull → implement → test → review → deploy → repeat.
Planning
An agent breaking a goal into steps before executing. ReAct (Reason + Act) is a common pattern: think, act, observe, repeat.
Capabilities
Tool Use / Function Calling
Giving an LLM the ability to call external functions with structured inputs. The model decides when and how. Used in story elaboration here.
Memory (Short-term)
The current context window — everything the model can "see" in this call. Lost when the call ends.
Memory (Long-term)
Persistent storage the agent reads/writes across calls. e.g. wisdom files, sdlc_pipeline.json. Must be explicitly loaded into context.
Design Patterns
Orchestration
Coordinating multiple agents or LLM calls to complete a complex task. The sprint pipeline (RE → clarify → elaborate → code → review → deploy) is orchestration.
Multi-agent
Multiple specialised agents working in parallel or series. Hello Scrum is single-agent + one reviewer (Hermes). Full multi-agent routes work to many coders.
Human-in-the-Loop
A human reviews and approves agent decisions at key points. FD approval and Hermes review are human-in-the-loop gates in Hello Scrum.
WIP (Work in Progress)
How many items an agent works on simultaneously. AI-DLC enforces WIP=1 — one story at a time. Limits cascading failures.
Evaluation & Observability
Testing
Eval
A test that measures whether an AI system produces correct or acceptable outputs. The foundation of knowing if your agent is improving or degrading.
Ground Truth
The known correct answer used to evaluate model output. Building ground truth datasets is expensive but necessary for rigorous evals.
LLM-as-Judge
Using an LLM to evaluate another LLM's output. Hermes is an LLM-as-judge — evaluates the coding agent's patches and AC compliance.
Benchmark
A standardised evaluation dataset used to compare models. e.g. MMLU, HumanEval. Useful for model selection; less useful for task-specific evals.
Metrics
Pass Rate
The percentage of stories that pass all gates (tests + code review + AC check). Hello Scrum's leaderboard tracks this per sprint.
Latency
Time from prompt sent to response received. stage_times in Hello Scrum tracks per-stage latency.
Cost per Call
Input tokens × input price + output tokens × output price. Haiku is ~20× cheaper than Sonnet. Hello Scrum uses Haiku for review, Sonnet for coding.
Operations
Tracing
Recording every step of an agent's execution — prompts called, responses, timing. The audit log is tracing in Hello Scrum.
Regression
A previously passing test that now fails. In agent systems, regressions often appear after prompt changes — improving one task can break another.
Fine-tuning & Training
Adapting Models
Fine-tuning
Further training a pre-trained model on a specific dataset to specialise its behaviour. Changes the model's weights. More durable than prompt engineering but more expensive.
Transfer Learning
Starting from a pre-trained model and adapting it for a new task. Almost all LLM work is transfer learning — you start from a foundation model, not scratch.
LoRA (Low-Rank Adaptation)
Efficient fine-tuning that only updates a small set of added parameters rather than the whole model. Cheaper and faster than full fine-tuning.
Prompt Tuning
Trains a small set of "soft prompt" tokens prepended to every input, while keeping the base model frozen. Lighter than fine-tuning.
Training Concepts
RLHF (Reinforcement Learning from Human Feedback)
Humans rank model outputs and the model is trained to produce more preferred responses. How Claude and ChatGPT learned to be helpful and harmless.
Loss Function
The mathematical measure of how wrong the model's predictions are. Training minimises this. For LLMs: cross-entropy loss on next-token prediction.
Gradient Descent
The algorithm that adjusts model weights to reduce loss. Calculates which direction to nudge each weight to improve predictions.
Overfitting
When a model memorises training examples instead of learning general patterns. Performs well on training data, poorly on new data.
Safety & Ethics
Alignment
Alignment
Ensuring AI systems do what humans actually want — not just what they literally asked for. An aligned model is helpful, harmless, and honest.
Constitutional AI
Anthropic's technique for training Claude using a written set of principles (a "constitution") rather than purely human feedback.
AI Safety
The field focused on ensuring AI systems remain beneficial as they become more capable. Includes technical alignment research and governance/policy work.
Threats
Bias
Systematic errors reflecting imbalances in training data. A model trained mostly on one demographic will perform worse on others.
Jailbreak
A prompt designed to bypass a model's safety guardrails. Usually involves roleplay, hypotheticals, or instruction injection.
Prompt Injection
Malicious text in the input overrides the system prompt's instructions. A key security concern for any agent that processes external content.
Red Teaming
Deliberately trying to break or extract harmful outputs from an AI system. Standard practice before deploying models or agents.
Controls
Guardrails
Rules or filters that prevent a model from producing harmful outputs. Can be in the prompt (instructions) or external (output classifiers).
Explainability
The ability to understand why a model produced a specific output. LLMs are largely black boxes — chain of thought is one way to surface reasoning.
