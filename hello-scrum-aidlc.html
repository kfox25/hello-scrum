Hello Scrum AI-DLC
Our implementation · adapted from AWS AI-DLC · single-agent · brownfield

The Pipeline

Inception → Sprint → Retrospective — end to end
Inception Phase
1
Intent Human
State what you want to build or change at a high level. Starting point for all AI-DLC decomposition.
intent string
2
Workspace Detection System
Scans the codebase to establish brownfield context. Reads live data model fields, status values, source values, and agent pipeline stages from sdlc_pipeline.json.
  • Detects languages, key files, item count
  • Reads actual field names and enum values from live data
  • Infers field types for complex fields — e.g. test_results: Array<{status, message}>, stage_times: object<{pull, deploy, …}>
  • Field types injected into elaboration, FD, and agent prompts — prevents structural guesses
  • Saves snapshot to workspace_context.json for downstream use
workspace_context.json
3
Reverse Engineering Haiku
Analyzes the existing codebase and produces a structured architectural overview. Brownfield only. Cached in reverse_engineering.json by item count — Re-run button forces fresh analysis.
  • Haiku produces: architecture summary, components, technical patterns
  • Server-side overrides: key endpoints, business transactions, code structure, business dictionary
  • Business dictionary: 14 Hello Scrum domain terms (Bolt, Hermes, Sprint, Inception, Unit…)
  • Code structure: 11 core app files only — reference/workflow pages excluded
  • All artifacts injected into Requirements Analysis and Elaboration prompts
architecture summary components business dictionary code structure reverse_engineering.json
4
Requirements Analysis Haiku
Classifies the intent and generates 4–6 targeted clarifying questions with A/B/C option chips. Workspace context is injected so questions are grounded in the actual codebase.
  • Assessment: Request Type · Scope · Complexity
  • Question categories: Users, Functional, Non-Functional, Constraints
  • Human selects answers or types free-form
assessment Q&A answers
5
Elaborate Sonnet
Decomposes intent + answers into one Unit with stories and sprint groupings. Workspace context and AC wisdom are injected so output references the real data model.
  • Unit = Epic (name + DDD domain label)
  • Stories = user stories with acceptance criteria
  • Bolts = suggested sprint groupings (Bolt = Sprint)
  • NFRs + Risks included
unit stories[] bolts[] nfrs[] risks[]
6
Add to Sprint Human
Review stories, edit as needed, then add a bolt (or all stories) to the sprint. Stories are written to sdlc_pipeline.json with source: "inception" and in_sprint: true.
sdlc_pipeline.json items
Construction Phase
7
Functional Design Human + AI
For each story in the sprint, Haiku generates a concrete implementation plan. Human reviews and approves before coding begins. Prevents the agent from misinterpreting story language into wrong file targets or data access patterns.
  • Haiku reads story + AC + workspace context + current index.html
  • Produces: patch_target, approach, elements to add/modify, risks
  • patch_target shown in green (index.html) or red (wrong file) — human gate
  • Approved FD saved to item in sdlc_pipeline.json and injected into agent coding prompt
  • Draft state: client-side only — not persisted until human clicks Approve
functional_design on item human approval required
Sprint Phase
8
Sprint Start System
Stamps sprint_number on all pending in-sprint items, then launches agent.py --sprint. Workspace context is loaded from workspace_context.json and injected into every story run.
sprint_number stamp workspace context injected
9
Agent Execute Sonnet
Implements each story as patches to index.html and a version.json bump. Workspace context tells the agent the exact data model, field names, and pipeline — preventing hallucinated implementations.
  • pull → story → code → test → deploy
  • Functional design injected as pre-approved implementation plan when present
  • Scope creep guard: max 3-line find block, replace must contain find
  • Up to 3 retry attempts on scope violations
  • Coding wisdom + workspace context injected from previous retrospectives
index.html patch version.json bump git commit + push
10
Hermes Review Haiku
Two independent review gates run sequentially. Both must approve for the story to deploy. Rejection rolls back index.html and marks the item failed.
  • Code Review — syntax, scope creep, broken selectors
  • AC Check — does the diff satisfy every acceptance criterion?
hermes_verdict rollback on reject
Retrospective Phase
11
Retrospective Haiku
Runs automatically after every sprint. Produces findings, then synthesizes two wisdom layers that feed back into the next sprint's coding and story-writing.
  • Sprint findings: failure patterns, success patterns, observations
  • Coding wisdom → injected into agent at next sprint
  • AC wisdom → injected into inception elaborate at next run
retrospective.json coding_wisdom.json ac_wisdom.json

Reference

Data flow, differences from AWS AI-DLC, models, and roadmap
A Context Data Flow

Workspace context flows from inception all the way to the coding agent — grounding every step in the real codebase.

Inception → workspace_context.json
Inception → reverse_engineering.json (cached)
workspace_context.json → clarify prompt (Haiku)
reverse_engineering.json → clarify prompt — architecture, business dictionary
reverse_engineering.json → elaborate prompt — components, transactions, dictionary
workspace_context.json → agent prompt every story (Sonnet)
retrospective.json → coding_wisdom → agent prompt
ac_wisdom.json → elaborate prompt

workspace_context.json regenerates every inception run — live field names, status values, source values. reverse_engineering.json is cached by item count and reused until Re-run is clicked or data changes.

B Models
StageModelWhy
Reverse Engineering claude-haiku-4-5 Architectural analysis from codebase summary
Requirements Analysis claude-haiku-4-5 Fast, cheap Q&A classification
Elaborate claude-sonnet-4-6 Quality story + AC generation
Agent (coding) claude-sonnet-4-6 Complex multi-patch code generation
Hermes (reviewer) claude-haiku-4-5 Fast dual-gate review
Retrospective claude-haiku-4-5 Pattern synthesis across sprint items
C How We Differ from AWS AI-DLC
Stage AWS AI-DLC Hello Scrum
Reverse Eng. Deep LLM analysis → architecture.md, api-docs.md, component inventory Built (step 3) — extracts routes, produces architecture summary, components, endpoints, cached in reverse_engineering.json
App Design Component boundaries, service layer, dependency graph Not yet built — deferred
Units Gen. Multi-unit decomposition, one unit per bounded context Single unit per inception run — multi-unit deferred
Bolts Sprint groupings across multiple units 1 bolt = 1 sprint. Stories run sequentially by one agent.
Construction Functional Design → NFR → Infrastructure → Code Gen → Build & Test Agent executes directly: code → test → Hermes → deploy
Target Any codebase, multi-file, multi-service index.html only — single-file test fixture
AWS AI-DLC is the reference standard. Hello Scrum is a working prototype — we add one stage at a time, validating before expanding.
D Roadmap — Stages to Add
Application Design Component boundaries, service layer design, dependency graph. Runs after Requirements Analysis when new components or services are needed.
Multi-Unit Inception Multiple units per inception run. Requires multi-agent execution — deferred until agent coordination is ready.
Human-in-the-Loop Flag Agent marks a story "needs human" when it detects uncertainty outside its scope — stops the sprint and surfaces the question.
Multi-File Agent Agent patches any file, not just index.html. Requires extending the deploy pipeline to commit arbitrary files safely.
