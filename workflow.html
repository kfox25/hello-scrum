Full Workflow

From Messenger idea to deployed feature
1 Capture — Messenger

You type a message in Messenger. Haiku asks one question: is this a story idea?

Idea Story idea — Haiku generates 2 alternative backlog titles (action-oriented, ≤10 words). Your original message appears as a third option, capitalized. All three are clickable — selecting any one adds it to the Opportunity Backlog with opportunity: true.
Other Not an idea — Haiku replies conversationally. Nothing is added to the backlog.
2 Elaborate — Backlog Board

You drag an item from Opportunity Backlog → Story Backlog. On drop, Haiku auto-generates a full user story (As a user, I want...) with 3–4 short, testable acceptance criteria.

The prompt is augmented with two wisdom layers: AC WISDOM (AC-writing directives from ac_wisdom.json, distilled from all past story outcomes) and CODING WISDOM (coding directives from coding_wisdom.json, distilled from all previous sprint retrospectives). Both inform how the AC are written before any code is run.

The card pulses with a "generating story..." animation while in flight. When done, a ▼ arrow appears at the bottom of the card — clicking it expands to show the AC and rotates the arrow to ▲. Expansion state persists across re-renders.

3 Sprint Planning — Backlog Board

You drag stories from Story Backlog → Sprint Backlog. Set an optional Sprint Goal in the field at the top of the sprint column. Order determines execution sequence — reorder to reprioritize.

When ready, click Start Sprint. The server spawns agent.py --sprint as a background subprocess and the pipeline takes over.

4 Start Sprint → Per-Story Pipeline — fully automated
a Wisdom + context injection. Before calling Sonnet, the prompt is built with two stacked sections: CODING WISDOM (synthesized cross-sprint bullet directives from coding_wisdom.json) and SPRINT WISDOM (absent on story 1 — story 1 relies on CODING WISDOM only; refreshed after each item so story 2+ sees the current sprint's raw findings). Only the changelog is trimmed — full index.html and wisdom bullets are sent as-is.
b Sonnet implements. Receives the story and AC from Step 2 as its brief, full index.html, and the last 1 changelog entry. Patches the file, bumps the patch version, adds a changelog entry.
c Automated tests (DoD). Nine checks run: index.html exists and contains title, version matches between version.json and index.html, deployed timestamp present in index.html, changelog has entry for current version, no CSS outside style block, no duplicate h1 rules, no duplicate body rules, no -webkit-text-fill-color, no mixed rgb/hex color formats. Fail → rollback, item marked failed.
d Haiku code review. Hermes reviews the diff for concrete defects only — syntax errors, broken HTML/CSS, scope creep. Design opinions, color choices, and accessibility judgments are explicitly excluded. Business requirements not evaluated here. Reject → rollback.
e Haiku AC check. Hermes checks whether the implementation satisfies the original idea and each acceptance criterion. Code quality assumed correct — purely requirements validation. Reject → rollback.
f Deploy. Git commit + push to GitHub. GitHub Pages goes live in ~30 seconds. Full audit trail (story, diff, test results, Hermes verdicts, timestamps, tokens) saved to sdlc_pipeline.json in the same commit.
5 Per-Story Retro — runs after every item
Wisdom Haiku analyzes all items processed so far this sprint. Writes findings to retrospective.json categorized as: Failure (recurring failure patterns), Success (what worked), Improve (suggested improvements), Observe (neutral observations).
Wisdom synthesize_coding_wisdom() passes the existing coding_wisdom.json bullets plus only this sprint's new findings to Haiku, which merges them — incorporating new patterns and dropping outdated ones — and rewrites coding_wisdom.json. First run bootstraps from full history.
Wisdom synthesize_ac_wisdom() passes the existing ac_wisdom.json bullets plus only this sprint's story outcomes to Haiku, which merges them and rewrites ac_wisdom.json. First run bootstraps from the last 50 story outcomes.
Context retro_context is reloaded from retrospective.json so the next story's SPRINT WISDOM block reflects what just happened — including whether the previous item passed or failed and why.
6 Repeat Until Sprint Empty

Steps 4–5 repeat for each story in the sprint queue. By story 3, the agent has seen what failed in stories 1 and 2 of this sprint (SPRINT WISDOM) plus the freshly updated all-time wisdom (CODING WISDOM). The feedback loops compound within the sprint.

When the queue is empty, the sprint ends. The Retro page shows all findings in the Sprint Retrospective column, and the Coding Wisdom and AC Wisdom panels on the right show the updated directives ready for the next sprint.
