System Workflow

How raw ideas become deployed features
You
AI Agent
System
1
Backlog You
Capture raw ideas in plain language. No structure needed — a vague description is enough. Ideas sit here until you decide to act on them.
Input A rough idea
Output Pending item in backlog.json
2
Sprint Planning You
Drag items from the backlog into the sprint on the board. Reorder to set priority. Only items in the sprint are picked up when you start a sprint.
Input Pending backlog items
Output Ordered sprint queue
3
Story + Implementation claude-sonnet-4-6
The worker agent reads the raw idea and does two things in one pass: writes a user story with acceptance criteria, then implements the change in index.html and version.json. Bumps the patch version and adds a changelog entry.
Input Idea, current index.html, version.json
Output Updated files, user story, AC, summary
4
Automated Tests (DoD check) test.py
Four checks run against the updated files: index.html exists and contains the title, version numbers match between files, deploy timestamp is present, and a changelog entry exists for the new version. Failure triggers an automatic rollback.
Input index.html, version.json
Output Pass / Fail + rollback on failure
5
Code Review claude-haiku-4-5
Hermes reviews the diff for technical quality only — bugs, broken HTML/CSS, scope creep, and implementation soundness. Business requirements are not evaluated here. Rejection triggers rollback; the item is marked failed.
Input Idea, story, diff
Output Approve / Reject + reason
6
AC Check claude-haiku-4-5
Hermes checks whether the implementation satisfies the original idea and each acceptance criterion. Code quality is assumed correct at this point — this is purely a requirements validation. Rejection triggers rollback; the item is marked failed.
Input Idea, story, AC, diff, test results
Output Approve / Reject + reason
7
Deploy git + GitHub Pages
Changes are committed and pushed to GitHub. GitHub Pages auto-deploys within ~30 seconds. The audit trail (story, diff, test results, Hermes verdict, timestamp) is saved to backlog.json and included in the same commit.
Input index.html, version.json, backlog.json
Output Live at kfox25.github.io/hello-scrum
7
Sprint Retrospective claude-haiku-4-5
After all sprint items are processed, a retrospective agent reviews the full sprint: what failed and why, what worked, and what could improve. Findings are written to retrospective.json and categorized as failure patterns, success patterns, improvements, or observations. Runs once per sprint — not per item.
Input All sprint item results (status, errors, verdicts, test results)
Output Findings + summary in retrospective.json
